## ① 14技法照合表

|---|---|---|
| ヒットストップ | なし | 被弾(2830/2849/2859)・die()(2945)・グレイズ(2985)いずれも時間停止処理なし |
| 画面シェイク | なし | "shake"該当コード0件（実装自体が存在しない） |
| スカッシュ&ストレッチ | 弱い | flapY(L2600)は機体ごとの常時呼吸アニメで、衝撃・被弾時の変形ではない |
| フラッシュ・白点滅 | 弱い | 被弾時のみ赤オーバーレイ`hitFlash`(L3722)。強さは0.35/0.4のほぼ固定2値。グレイズ・コイン・クリアには画面フラッシュなし |
| パーティクル | あり | emitSparkle/Puff/Flame/CometJet等種類豊富。コインはkind(big/small)でn・spreadを変えるが、被弾は8個・スプレッド固定 |
| ノックバック | あり | 被弾時hvel付与(L2831/2859)。強さはほぼ一定(200〜280)で"効いた度合い"の翻訳が薄い |
| 数字・テキストポップ | あり(弱) | +val浮遊フェード(L2923/3707)。フォントサイズ・色は全イベント共通、値の大小で見た目は変わらない |

| 無音の間 | なし | タイミング制御による意図的な間の演出は見当たらず |
| 画面フチ・ビネット | 実装はあるが用途外 | menuBG()(L3847)で常時装飾用途のみ。プレイ中のHP危機など状態可視化には未接続 |
| UIのバウンス | あり(弱) | クリア星のpop(L3806, 1+0.12*sin)、grazeComboのpulse(L3294)。被弾・コイン取得側にはバウンスなし |
| カメラのキック/ズームパンチ | なし | camOffsetはイントロ専用(L2708)。被弾・撃破時の意図的カメラキックはなし |

**原則1（強弱の段階化）**: 明確な段階化はコインのkind差（big/small）くらい。被弾・グレイズ・バックドラフト各種は強度がほぼ固定値で並んでおり、「小・中・大」の区別を画面上で翻訳できていない。
**原則2（複数チャネルの重ね）**: 被弾＝音1+粒子+赤フラッシュ+ノックバックで4chと最も手厚い。グレイズ＝音1+粒子+テキストで3ch。バックドラフト発動＝粒子(22〜38個・機体別配色)+リングは豪華だが音は`sfx('tap')`のみ→画が音を置き去りにしている（詳細は②-4）。

## ③ 改善候補

1. **バックドラフト発動に専用SEを足す**（技法＝SEレイヤー／強める行＝#4）。現状`sfx('tap')`使い回しが最大の穴。既存sfx()にレイヤー合成（打撃+抜け音の2オシレーター）を1種追加するだけで済む。素材＝コードで済む。工数＝小（半日）。
2. **グレイズに画面反応を1段足す**（技法＝フラッシュ・白点滅 or カメラキック／強める行＝#2）。被弾の赤フラッシュに対し、グレイズ側にも淡い金色フラッシュか小さなズームパンチを追加し、"成功の方が強い"バランスに反転させる。素材＝コードで済む。工数＝小。
3. **危険側コインの演出差別化**（強める行＝#2）。pickupValue()にリスク位置フラグを足し、危険側コインだけ粒子数/色/テキストサイズを1段上げる。素材＝コードで済む（既存sparkle/popup流用）。工数＝小〜中（判定ロジック追加要）。
4. **被弾/危機の段階化**（技法＝強弱の段階化＋画面フチ・ビネット／強める行＝#3）。hitFlashを固定値でなく残HP依存で強度を変え、HP1（瀕死）時のみビネットを常時点灯させ状態を常時可視化する。素材＝コードで済む。工数＝中。
5. **画面シェイク or ヒットストップを被弾・撃破に新規導入**（技法＝画面シェイク／ヒットストップ／強める行＝#2,#3）。カタログの2大定番技法が丸ごと未実装。数フレームの停止・数px振動程度からで良い。素材＝コードで済む。工数＝小（各数行）だが酔い・視認性への配慮チューニングに時間を要するため中評価が妥当。
6. **更新気流の搭乗にSEを足す**（強める行＝#6）。搭乗開始のワンショット＋搭乗中のループ音（ピッチ変調）で解放感を音でも翻訳。素材＝SE要（合成音でも可）。工数＝中。

## ④ カタログ側の不備フィードバック

- カタログの「SEのレイヤー」行は"複数音源のミックス"を前提にしているが、hippo-rocketのように**WebAudioの単一オシレーター合成のみ**で音を作る軽量実装が前提のプロジェクトでは、「レイヤーを足す最小単位」の目安（例：オシレーター2本の周波数差だけでも"層"になる、という最小コスト版の書き方）が抜けている。素材要否の欄が「SE要（複数素材）」固定になっており、"素材なしで層を増やす"選択肢が読者に伝わりにくい。
- 「強弱の段階化」の原則は書かれているが、**どの技法がどの変数（HP・コンボ数・危険度など）に連動して段階化すべきかの対応表がない**ため、監査時に「段階化しているか」を判定する軸が実装者の裁量任せになっている。今回の監査でも「コインのkind」以外に段階化の軸が見当たらないという判定になったが、これがカタログの基準の甘さなのか実装の手薄さなのか切り分けにくかった。
