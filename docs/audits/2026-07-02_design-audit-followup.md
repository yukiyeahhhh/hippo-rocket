- ただし、29項目の表そのものは現時点でリポジトリにも knowledge にも見つからない。
- 本文書は、ユーザーが共有した監査抜粋と、現在の `index.html` / 設計文書を照合した要対応メモ。

## 共有された監査抜粋

- 「押しすぎ」を罰する敵が機能していない。ペリカンが実質スイフトと同じ避け方になっている。
- ハートが設計と正反対。設計では「危険に置いてリスク/リターン」と書いているが、実装は敵のいない安全地帯にだけ置かれている。
- ボーナス回廊が「欲張りの決断」を作っていない。敵なしでコインだけなので目的不在。
- シャッター/ステップゲートが既存敵と役割被り。
- 支配的戦略の懸念3件が実機未検証のまま。

## 対応方針

1. **監査レポートを再生成して保存する**
   - `07-設計監査スキル.md` の形式で、現在の設計文書と `index.html` を再監査する。
   - 次回から要約だけでなく、表そのものを `docs/audits/` に残す。

2. **L0の穴を先に直す**
   - ペリカンを「押しっぱなしでは損をする」部品に戻す。
   - ただし全機体が通れる通路保証は維持する。ふうせんが詰む縦回避専用にはしない。

3. **報酬の目的を分ける**
   - ボーナス回廊は「休符/気持ちよさ」として残すなら、その名前と役割を明記する。
   - 欲張り報酬は、別ビートとして危険側コイン/ハート/大コインに寄せる。

4. **ハートをいったん保留または危険側へ移す**
   - 安全地帯ハートは、監査上は目的不在。
   - 回復を残すなら、ダイブ/上かぶり/フロート周辺の「取りに行くリスク」がある位置へ置く。

5. **支配的戦略は自動プレイテスト要件へ接続する**
   - 文書監査では「未検証」までしか言えない。
   - `08-自動プレイテスト要件定義.md` の方針どおり、簡易方策での検出対象にする。

## バックドラフト案との関係

Gemini案の「固有バックドラフト」は、落下を能動化する方向として筋が良い。ただし、上の監査指摘を放置したまま全機体へ入れると、既存のL0不備を新システムで覆うだけになる。

推奨順は、ペリカン/報酬のL0修正 → `ふつう` と `コメット` の2機体だけでバックドラフト試作 → 再監査。
